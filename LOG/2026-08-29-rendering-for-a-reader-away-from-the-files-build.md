# [HASH] — Pointing stays the default, and a reader who cannot open the file can say so

The render rule was unconditional and deliberately so, on the reasoning that a reader away from the file is served by the plain-English summary opening each item's discussion. That reasoning assumes the reader *could* open the file if they wanted to. On remote control there is no filesystem to open, so the pointer resolves to nothing — fine for one queue item, not fine for a fourteen-part deliverable being approved item by item.

The absolute sentence was reworded out in the same edit that added the trigger, rather than a limb being bolted beside it, because a new exception would have contradicted it rather than extended it. What replaces it takes the shape the show-first block already uses: the user says they cannot open the file, and doc-resident text comes into the message for the rest of that chat. Nothing is stored and the switch moves one way, toward more showing.

Two things the build was told not to do, and did not. **No detection and no asking** — the user's own correction, that inferring where she is defeats the purpose and re-creates the over-asking this method has spent months removing. And **no named mechanism**: the route that worked once stays out of the rule, because naming it would be a capability claim about every consumer's setup.

`next.md` carried the same absolute sentence at its present-the-run beat. That file was added to the run's list before it was edited, and the item's own observable is what required it — the grep it names covers the shipped docs rather than one file, so leaving it would have shipped the rule beside its own contradiction.
