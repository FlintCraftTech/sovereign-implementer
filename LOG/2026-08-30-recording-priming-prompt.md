# [HASH] — Reusable priming prompt for recorded demo sessions

The user's idea, raised in the site project's planning session and mailed here on 2026-08-28 as the side that owns it. A prompt pasted at the start of any session being recorded: this is a demo, keep revealing information off the screen. Her reason, carried from the mail — a recording exposes more than the method being shown, and preventing it at the source is far cheaper than blurring it in the edit afterwards.

Both videos went scripted at processing, which shrinks this prompt's job without removing it. The risks live in the margins a script does not cover: a session opening listing other projects' names, a file path carrying the username, a mailbox line naming a correspondent, an autocomplete showing real folders. Those arrive uninvited, which is what a standing prompt is for.

`YouTube/recording-priming-prompt.txt` carries five instructions — stay inside this project, never echo an absolute path, never touch the mailbox or its address book, use invented names and data only, and where a step would put something real on screen say so and stop rather than improvising a redaction. It closes by naming why it is standing rather than something the user remembers to ask for.

The folder is gitignored, so the wording is hers to tune by hand at any time.
