# 778d6a3 — Co-writing settles as two rule amendments, not a new flavour

Raised by the user on 2026-08-28 mid-walk-through of the law-prose article: co-authoring is both her work and Claude's, works slightly differently each time, and — her words — "we always have to just kind of shove it in there somehow". The lived instance was that article's fourteen-claim list, planning-type work performed inside a walkthrough and delivered as fourteen approval turns.

No new flavour, and the reason is recorded so it is not re-opened: a flavour changes how /next routes an item, and co-writing routes exactly like any `[user]` walkthrough. What differs is the content, which the walkthrough shape already handles. Refused earlier and still refused: processing each claim the way /plan processes a capture, which the user judged too tedious.

Two amendments, each to a named parent. The inversions block gains the missing case — a claim or example set **produced by** a walkthrough step is delivered together and contested by number. The block's existing exclusion of `[user]` items as "driven live, always sequential" stays untouched: that governs the items, this governs a set a step produces. The authoring standard's deliverable arm gains the consequence — a deliverable's text never lives inside a queue entry; the entry points at the file where the deliverable lives and carries the reasoning about it.

The second amendment is the general form of the user's rule of 2026-08-30: planned writing never goes in the queue, and captures about the writing point at the pieces. The mechanical extraction of the three post drafts is separately owned by [post-drafts-leave-the-queue].

The outbound message about co-writing that this item's earlier text holds back is unchanged and still unsent, on her instruction of 2026-08-28.
