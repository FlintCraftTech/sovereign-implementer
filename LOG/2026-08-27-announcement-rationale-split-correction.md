# The rationale-split announcement is dropped, not corrected

`[user]` item [announcement-rationale-split-correction], walked through in the
2026-08-27 /next run and **deleted on the user's explicit direction** — her
words: *"I say drop it."*

## What the item was for

It was filed 2026-08-09 because an unposted Discord draft told readers the
reasoning behind the method's rules "lives in the session logs where you can go
and read it" — false for every reader not developing the method, since the
plugin package ships neither `LOG/` nor `resources/`. The item's job was to
correct that sentence and decide, at drafting, whether the announcement was
still worth making at all.

## What this session found before drafting

The original draft is not stored anywhere. `LOG/2026-08-09-self-authoring-rules.md`
*describes* it and quotes the one false clause, but the post text itself was
never recorded. So step 1 was a fresh draft rather than a patch — which the item
had anticipated, telling a later session to check the whole thing rather than
only the false sentence.

A second finding, offered and accepted: as **news** the subject is stale — it
shipped over two weeks ago with no release behind it — but under the two-kinds
posting rule built earlier in this same run it fits the **tip** test, which needs
no event. That removed staleness as a reason to drop it, and moved the decision
onto the content.

## Why it was dropped, in the user's own terms

She read the draft and rejected it on five counts, each of which lands:

- it claimed the reasoning "was making the rules harder for *you* to read" —
  users do not read Throughliner's rules;
- it opened with "the reason you'd feel" — there are no current users, so
  nobody experienced the before or the after;
- it presented the FAQ as the new home for consumer-facing why — but the FAQ
  is where users were always meant to look, so nothing changed for them;
- it said authoring reasoning stays in the development log — nobody outside
  this project has a reason to care;
- it explained that the FAQ fills as features are announced — same problem.

**The diagnosis, which is the part worth keeping.** The draft described an
internal reorganisation and dressed it in second-person benefit language. Every
sentence was true and none of it was news to anybody, because the whole change
happened on the far side of a boundary the user never crosses.

**Her one constructive note, recorded and captured rather than acted on now:**
the genuinely interesting story is *why* the why-clauses were removed at all,
which the draft omitted entirely — and its natural home is a larger announcement
alongside the upcoming law-prose article. She set that aside for now
("that's neither here nor there"); it is filed as
[law-prose-article-announcement-carries-the-why].

## What this says about the posting brief, noted not filed

The draft satisfied the brief's stated shape — benefit first, plain words, no
decision history — and was still worthless, because the brief tests how a claim
is *worded* and not whether the subject changes anything for a reader. The
two-kinds test added earlier today is closer to the right question, and this
draft passes it too: it does explain one feature. Neither test catches "the
feature is invisible from the user's side". Recorded as an observation about the
tests rather than filed as work, since one instance is not yet a pattern and the
project bans speculative rules.
