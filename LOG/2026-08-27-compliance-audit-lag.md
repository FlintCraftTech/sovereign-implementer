# [HASH] — Compliance sweep over the rule-bearing commits since the last audit: seven findings

Filed by the rule checks at the previous close under the slug they print. The item carried a written file list and also told the audit to recompute it, since the check reads it from git — so the recomputation was run and used. It returned **eight** files under delta scope: `CLAUDE.md`, `done-build.md`, `done-plan.md`, `done.md`, `feedback-and-inbox.md`, `migrate-checklist.md`, `next-audit.md`, `next-build.md`. The item's own list named five more from its own session; the recomputed list is what the audit ran on, exactly as instructed.

**Axis stated before the first read, as the checklist requires: the parent axis.** A doc is compared against its parent, never its sibling — a child restating what its parent carries is genuine duplication because the reader has both loaded, while two parallel docs sharing wording are parallel by design.

**Seven findings, by lens.**

*Tag placement.* Both child close docs' Commit steps carry no response-shape tag while their parent's Commit core carries `[BRIEF, PROMPT]` — and the inconsistency is internal, since `done-build.md`'s neighbouring Staleness sweep is also a bare pointer at a parent section and does repeat the parent's tag. The commit is the one step the method always shows and waits on, so a missing `[PROMPT]` leaves that wait to chance. Separately, `feedback-and-inbox.md` carries no tags **anywhere**, though every section it has ends in something leaving the machine on an explicit yes — the doc encodes in prose what the tags exist to encode.

*Decision history in operative text.* `feedback-and-inbox.md` narrates its own superseded earlier version — what a previous draft rejected and why that is now overturned — in a doc that ships to consumers who have no interest in which version rejected what. The delete-and-read test is clean: remove it and a complete instruction remains. And `done-plan.md` carries a "repealed — do not reinstate" block whose audience is a future method author, which is never a consumer, in a doc every consumer loads.

*Narration drift.* The reorder specimen in `done-plan.md` shows the user bare slugs — the exact output the always-loaded vocabulary rule forbids, in the one line the user reads about an ordering decision made on their behalf. A specimen is stronger than a rule because it is what gets copied. And `next-audit.md`'s halt specimen offers a flat menu at a moment the same doc has a stated preference, which the dependency-ownership rule names as a menu where a recommendation was due.

*Self-authoring, eviction debt.* `next-audit.md` restates the empty-Files-list rule its parent already carries. The parent's fires at scope-lock, when the list is being derived; the child's fires later, when the list is already locked and cannot change — so this is not two plugs in two holes, and the restatement never repealed its prior.

**Each finding names where each site fires**, which is the checklist's guard against a false duplication surviving to processing weeks later.
